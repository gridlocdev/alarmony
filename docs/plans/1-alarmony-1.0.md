# Alarmony 1.0 slices

Each slice leaves `just check` green and the app working.

- [x] **1. Skeleton and first slice** (§3.1–§3.4, §4, §5, §8, §11, §13, §14 partly, §15 partly): workspace, engine (format, `classifyFile`, operations, undo, stopwatch and timer arithmetic, durations), stores (memory, browser, desktop file), the save session, the app shell (tabs, catalog, ⌘K, ⌘/, Settings, theme, notices), the Stopwatch and Timers tabs, timers ringing in the window with one built-in sound, the Electron shell with headless mode, tests and e2e. Waits on nothing.
  - Done as planned, with these left for later slices (the PRD sections stay as written):
    - Only the Stopwatch (⌘3) and Timers (⌘4) tabs. A saved World Clock or Alarms tab opens Timers.
    - A save conflict always asks (Keep Mine / Use Theirs); replaying edits on the other copy is slice 5. A refresh that finds an outside change replaces the document and clears undo.
    - A file from a newer Alarmony refuses to open instead of opening read-only.
    - The browser keeps clock.json in its private file system (OPFS) only.
    - One sound, Chimes.
    - The desktop folder is `ALARMONY_FOLDER` or Documents/Alarmony, with no first-start question. Closing the window closes it; it doesn't hide (slice 3).
    - No native notifications and no right-click menus: each timer card's buttons and × do what its menu would. Renaming a preset waits for its menu.
    - Stop on the ringing sheet stops the sound; the timer's card stays Done until Dismiss or Restart.
- [x] **2. Alarms** (§7, §9, §10): the list and editor, `nextDue` with DST, the scheduler, the ringing sheet, snooze, notifications, all eight sounds, missed alarms.
  - Done as planned, with these left for later slices (the PRD sections stay as written):
    - The menu-bar Stop and Snooze wait for the tray (slice 3). Clicking a notification shows the window.
    - No right-click menu on alarm rows: the switch and × do what it would. Duplicate Alarm is in ⌘K and the menu bar.

- [x] **3. Desktop in the background** (§15): tray with countdown and menu, hide on close, quit warning, open at login, power-save blocker, wake handling, first-start folder question, window state. Waits on 2.

    - Don't Show Again and Don't Ask Again are checkboxes on the system dialogs; the answers are kept in `prefs.json`. The first-start question also has Quit (Esc).
    - Only the packaged app adds itself to the login items; a development run leaves them alone.
    - The tray, the dialogs and the power-save blocker are only checked headlessly as far as they can be: the menu and its state by unit tests, hiding on close and waking by the desktop scenario. The tray itself and the real dialogs need a look in a packaged build.

- [x] **4. World Clock** (§6): zone search, cards with analog faces, list view, reorder.
  - Done as planned, with these left for later:
    - Reordering is by ⌥↑ and ⌥↓ (and Move Clock Up / Down in ⌘K and the menu bar); dragging a card waits for the polish slice.
    - No right-click menu on a clock: its × deletes, a double-click renames.
    - A place at the same time as this device says "Today, same time".
    - The app now opens on World Clock the first time; after that, on the last tab.
- [x] **5. Changes made elsewhere** (§3.5, §3.6): replay and conflict dialog, refresh timers, crash snapshot and recovery.
  - Done as planned, with these notes:
    - Replay puts this window's net change onto the other copy, not each operation in turn, so an edit made and undone here takes nothing back from the other side.
    - Fields that only make sense together change together: an alarm's time, days, on/off and one-time date; a timer's length, run state, end time and time left. Changing any of them on both sides is a clash.
    - A file from a newer Alarmony met while merging stops saving with "Couldn't save." and the newer-file message, until the user updates or Try Again finds it gone.
    - The browser keeps one snapshot slot per tab, held by a Web Lock; a snapshot from an older build (one slot, the whole file) is still offered and restored as a change on top of the file.
    - Checked by unit tests (random edits on both sides, the session and the save chart) and browser scenarios for a merge, Keep Mine and Use Theirs. The desktop app shares the page's code; it wasn't checked with two windows.
- [x] **6. CLI** (§12) with its agent skill file.
  - Done as planned, with these notes:
    - Exit codes follow §12: a wrong command line exits 1, not the 2 many tools use, so 2 always means a conflict.
    - An edit is computed on the file as read, then saved with the lock file and version check; a file changed meanwhile is re-read and the edit replayed onto it (once), and a clash on the same item exits 2 with nothing saved. A file deleted meanwhile is written again.
    - The CLI runs from TypeScript source on Node 22.18 or later (`just cli <args>`, or `apps/cli/bin/alarmony.mjs`); it isn't bundled or published.
    - `folder.json` and the desktop app's data folder moved to `packages/node-files`, so the CLI finds the same folder as the app.
    - `apps/cli/skill/SKILL.md` is the guide for agents; a test checks it names every command, and another that `man` and `schema` cover them.
    - Checked by unit tests that run every command in-process on a temp folder with a fixed clock, including a merge, a conflict and `--wait`.
